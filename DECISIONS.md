## 2026-11-22 — ARQ on Windows & Upstash Polling Budget (Phase 0 Spike 4)
- **Windows execution:** Native Windows `arq.exe` runs and processes jobs cleanly (`0.30s` pickup, `0.00s` execution against Docker `redis:7-alpine`), so WSL2/Docker-wrapped workers are not strictly required for local Windows development. Note: Windows lacks POSIX `SIGTERM` graceful-shutdown signal handling via `TerminateProcess`; use Dockerized workers in production Linux.
- **Port conflict note:** Host port `6379` was already bound by another project's Redis container on this machine. Standardized `rezoooo.me` local Redis on host port **`6380`** (`127.0.0.1:6380:6379` in compose and `REDIS_URL=redis://127.0.0.1:6380/0` in `.env.example`, `AGENTS.md`, and planned root `docker-compose.yml`).
- **Upstash free-tier analysis:** Upstash Redis free tier allows **500,000 commands/month** (`~11.57 cmds/min` sustained across the whole month). Measured idle ARQ `ZRANGEBYSCORE` polling per worker:
  - `poll_delay=0.5s` (default): `118.0 cmds/min` -> `5,097,600/month` (1 worker) / `10,195,200/month` (2 workers — **20.4x over free tier**).
  - `poll_delay=5.0s`: `12.0 cmds/min` -> `1,036,800/month` (2 workers — **207.4% of free tier**).
  - `poll_delay=15.0s`: `4.0 cmds/min` -> `345,600/month` (2 workers — **69.1% of free tier**).
- **Recommended production `poll_delay`:** For Upstash free tier, configure **`poll_delay = 15.0s`** (or `default=12.0s`, `ocr=25.0s` for `~320k idle cmds/month`), leaving ~155–180k monthly commands for actual jobs and quota checks while remaining inside the 20–60s completion target. For sub-2s pickup latency (`poll_delay=2.0s` / `10.0s`, ~1.56M cmds/month), use Upstash Pay-As-You-Go (`$0.20 / 100k commands`). Keep `poll_delay=0.5s` locally on Docker Redis.

## 2026-11-22 — LLM Provider Switch: OpenCode -> OpenRouter (`inclusionai/ling-3.0-flash-vl`, Phase 0b Spike 1)
- **Routing & Metadata (`1a`):** Replaced OpenCode with OpenRouter (`OPENROUTER_BASE_URL=https://openrouter.ai/api/v1`, `OPENROUTER_API_KEY`, `LLM_MODEL=inclusionai/ling-3.0-flash-vl`). OpenRouter endpoints API confirmed `inclusionai/ling-3.0-flash-vl` has context `131,072`, `max_completion_tokens=32,768`, pricing `$0.06/1M` input, `$0.18/1M` output, `$0.012/1M` cache read, `17` supported parameters, and **only 1 provider (`DeepInfra`, slug `deepinfra`, tag `deepinfra/fp4`, quantization `fp4`)**.
- **`data_collection="deny"` & Strict `json_schema` Findings (`1b`–`1c`):**
  - `data_collection="deny"` with `allow_fallbacks=False` was accepted (`HTTP 200`, `provider=DeepInfra`) once `max_tokens` was raised from `2048` to `4096` — DeepInfra is **not** excluded by `data_collection="deny"`.
  - Under `response_format={"type": "json_schema", "strict": True}` with `provider.require_parameters=True`, `ling-3.0-flash-vl` passed only **`13/20`** (`p50=10.76s`, `p95=20.99s`): 6 calls entered infinite `\n` / `\t` whitespace repetition loops (verified reproducible even at `max_tokens=4096` and default reasoning), 1 truncated, and some valid calls returned empty `improvements=[]`.
  - Under naive `tools`, DeepInfra rejected Pydantic's `#/$defs/ResumeEntities` with `HTTP 400` (`Failed to compile json grammar: Cannot find field $defs`).
  - **Working solution:** Inlining `$defs`/`$ref` directly into the tool schema (`tool_calling`) + `reasoning: {"enabled": False}` + `max_tokens=4096` + `data_collection: "deny"` + prompt/Pydantic non-empty feedback checks achieved **`20/20` valid** (`20/20` non-empty improvements), `min=5.62s`, **`p50=10.85s`**, **`p95=18.02s`**, `max=20.39s`, avg `1707.7` input / `1469.4` output (`0` reasoning) = `3177.1` tokens, and **`$0.000304/call`** (`usage.cost`). All 5 mismatch-control & prompt-injection cases (`inj_0..4`) produced valid JSON with `fit_score` of `0, 0, 5, 2, 0`.
- **Failure / Outage / Fallback Plan (`1d`–`1f`):**
  - Timeout (`0.05s`) cleanly raised `openai.APITimeoutError`. Simulating DeepInfra outage (`ignore=["deepinfra"], allow_fallbacks=False`) failed with `HTTP 404 NotFoundError` (`endpoint_count: 1`). Live `429` exhaustion was not induced (unverified live); production `LLMClient` caps worker LLM concurrency, respects `Retry-After`, retries transient `429`/`5xx`/timeouts with exponential backoff + jitter (3 attempts), sets **`45s`** timeout on primary (`60s` on fallback), and fails over to **`qwen/qwen3.8-flash`** (`Alibaba`, slugs/tags `alibaba/us-east-1` & `alibaba`, 1M ctx, `$0.15/$0.47` per 1M).
  - Fallback observations: `qwen/qwen3.8-flash` scored `11/20` at `max_tokens=2048` with reasoning ON (9 long-resume truncations, 5/5 injection resistance `fit=0..2`), and passed all 3 follow-up long-resume probes at `max_tokens=4096` with `reasoning.enabled=False` and `data_collection="deny"` (`allow_fallbacks=False` -> `HTTP 200`, `Alibaba`, `28.64s`, `$0.001013/call`; full 20-call Qwen re-run at `4096` remains unverified). `meta/muse-spark-1.3-contributor` (`Meta`, 1M ctx, `$0.10/$0.20` per 1M) is excluded because Meta's terms allow prompts/outputs to be used to improve Meta's products, which is unsuitable for real user resumes.

- **`DELETE /me` Strategy (Spike 2b):** `POST /delete-user` returned `HTTP 404` under cookie, `Bearer <session_token>`, and `Bearer <jwt>`. Live `pg_constraint` inspection confirmed `neon_auth.{account, session, member, invitation}` all reference `neon_auth."user"(id) ON DELETE CASCADE`. Transactional SQL `DELETE FROM neon_auth."user" WHERE id = $1` dropped `(user, account, session)` counts from `(1, 1, 1)` to `(0, 0, 0)`, invalidated `GET /get-session`, and rejected `POST /sign-in/email` (`401`). Therefore, Phase 2 `DELETE /me` will delete S3 files, `analyses`, `usage_daily`, and `neon_auth."user"` via SQL (avoiding storing a `NEON_API_KEY` on the backend), AND FastAPI's token check MUST reject JWTs for users who no longer exist (since 15-min JWTs stay valid until `exp`).
